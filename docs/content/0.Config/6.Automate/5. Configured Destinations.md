Based on the source code and UI files you provided, the **User Destinations** (specifically the "Configured Destinations" section) acts as the master routing engine for bulk vehicle data on the WiCAN Pro.

### The Purpose of Configured Destinations

Instead of flooding your network with individual MQTT messages the exact millisecond each PID responds, this section acts as an aggregator.

Whenever you configure a PID in your Vehicle Groups to use the **`Default`** destination type, it is handed over to this engine. The firmware sweeps up all of those `Default` PIDs, bundles them into a single, unified JSON "snapshot" (along with your CAN filter data), and pushes that payload to the external services or MQTT brokers you define here.

This allows you to push massive amounts of vehicle telemetry to Home Assistant, custom HTTP servers, or A Better Routeplanner (ABRP) in one highly efficient batch.

### Breakdown of the Fields

The Javascript (`main.js`) dynamically generates different fields depending on the protocol you select. Here is exactly what each field does:

* **Enabled (Checkbox):** Toggles this specific routing rule on or off.
* **Stats (OK / Fail):** A live counter showing how many payloads were successfully delivered versus how many failed (due to network drops, bad authentication, or timeouts).
* **Type:** The protocol used to transmit the JSON snapshot.
* `Default` or `MQTT Topic`: Pushes the JSON payload to an MQTT broker.
* `HTTP POST` / `HTTPS POST`: Pushes the JSON payload to a web server.
* `ABRP API`: Specifically formats the data into telemetry metrics (State of Charge, Power, Speed, etc.) and routes it directly to A Better Routeplanner.


* **Cycle (ms):** This controls the pacing of the data push.
* **Timer-Driven (`>= 1000`):** If you enter `5000`, the WiCAN buffers the vehicle data in RAM and only pushes the JSON snapshot to this destination every 5 seconds.
* **Event-Driven (`0`):** If you enter `0`, the WiCAN instantly pushes the payload the exact millisecond a polling group finishes its batch.


* **Destination:** The target address. If you selected an MQTT type, this is the MQTT topic (e.g., `vehicle/telemetry`). If you selected HTTP/HTTPS or ABRP, this is the full URL endpoint. *(Note: Leaving this blank for MQTT defaults to your global WiCAN RX topic).*
* **Auth (HTTP/HTTPS Only):** Allows you to select how you authenticate with your custom server. It dynamically expands to let you input:
* `Bearer Token`
* `API Key` (sent as a custom Header or embedded in the Query string)
* `Basic` (Standard Username & Password)


* **API Token / API Key (ABRP Only):** The specific user token provided by your A Better Routeplanner account so the WiCAN can map the live telemetry to your active driving session.
* **Query Params (HTTP/HTTPS Only):** Allows you to append custom Key/Value pairs to the end of your URL (e.g., `?device=truck&user=admin`).
* **Cert Set (HTTPS Only):** Allows you to select a specific SSL/TLS Certificate (managed in the System tab) to ensure the WiCAN securely trusts the server it is posting to. Defaults to the embedded standard certificate authorities.
